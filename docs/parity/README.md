# Parity with @fundamental-ngx/core: stories and tests

This report compares every component in `registry/ui/` with `@fundamental-ngx/core` in two ways:

1. **Stories vs. upstream examples**: each example on the component's page of the
   [core docs](https://sap.github.io/fundamental-ngx/#/core/home) against our `<name>.stories.ts`.
2. **Tests vs. upstream specs**: the behaviours checked by `libs/core/<name>/**/*.spec.ts` in
   [SAP/fundamental-ngx](https://github.com/SAP/fundamental-ngx/tree/main/libs/core) against our `<name>.spec.ts`.

It is the input for a series of follow-up pull requests that fill the gaps (see [Plan](#plan)). The per-component detail,
with one row per example and per behaviour, is in [`components/`](components/).

## Method

- **Upstream version:** `SAP/fundamental-ngx` `main` at
  [`3879bc0`](https://github.com/SAP/fundamental-ngx/tree/3879bc03796ed8d72d759e3891e873f20cf4a5ed), October 2026.
- **Examples** come from the docs sources the site is built from: each `<fd-docs-section-title>` in
  `libs/docs/core/<page>/*-docs.component.html` is one example, and the page list is the site navigation in
  `libs/docs/core/docs-data.json`. The live site itself could not be opened from the analysis environment, so it was not
  checked visually.
- **Tests** are grouped into behaviours (roughly one per upstream `describe`, near-duplicate `it`s merged), so the
  counts below are behaviours, not `it` blocks.
- **Status:** ✅ covered · 🟡 partial (exists but misses variants, states or assertions) · ❌ missing · ➖ n/a. A
  behaviour is n/a when it has no meaning in this port: "should create", NgModule/DI and zone plumbing,
  fundamental-styles class names checked for their own sake, and APIs the port deliberately dropped. Where a class
  encodes a state (`is-disabled`, toggled, selected), the state is in scope and must be tested through ARIA or the
  token classes.
- **"Open story missing"** means the component has an overlay (popover, menu, dialog, list, tooltip) and no story
  named "Open: …" that opens it, so `pnpm test:a11y` never runs axe on the overlay.
- **Name mapping:** `feed-list` ← `feed-list-item`; `form` ← `form-message` and core `form`; `input` ← the `input` and
  `textarea` pages and the core `form` specs; `list` ← the `list`, `list-byline` and `list-subline` pages; `settings` ←
  `settings-dialog`; `nested-list` has no page of its own, so its examples come from `side-navigation` (they overlap).
- The comparison was done per component by reading both sides' sources. It is a judgement, not a script: treat
  single rows as a starting point and re-check them when you pick the work up.

## Summary

92 components, 439 stories, 744 tests in the registry.

|                     | Total | ✅ covered                | 🟡 partial | ❌ missing | ➖ n/a |
| ------------------- | ----- | ------------------------- | ---------- | ---------- | ------ |
| Upstream examples   | 626   | 448 (72%)                 | 96 (15%)   | 82 (13%)   | —      |
| Upstream behaviours | 953   | 416 (53% of 786 in scope) | 152 (19%)  | 218 (28%)  | 167    |

Main findings:

- **`pnpm test:a11y` is red on `main`** in two stories. See [Failing a11y stories](#failing-a11y-stories-on-main).
- **Overlays are the biggest a11y hole.** 40 of 92 components have no "Open: …" story for their overlay, so axe has
  never checked a select list, a combobox or picker popup, a menu opened from a split button, tabs or toolbar, a token
  or avatar-group popover, a toast, or a message-strip alert. Some components open on load through an `autoOpen` input
  instead of `play` (dialog, notification, product-switch). axe still checks them, but this doesn't follow the
  convention in `CLAUDE.md`.
- **Test gaps sit in the complex, interactive components.** These have the most missing behaviours: multi-input (12),
  product-switch (12), dynamic-page (11), menu (10), multi-combobox (10), select (10), dialog (9), popover (9),
  notification (8), combobox, date-picker, datetime-picker, grid-list, avatar, message-box and step-input (6–7 each).
  The missing tests cover keyboard, focus return, form/CVA state, mobile dialogs and the programmatic API.
- **Story gaps are concentrated too.** list (12 missing + 3 partial of 26), popover (7 + 3 of 20), card (5 + 6 of 17),
  dynamic-page, content-density (no stories at all), combobox, multi-combobox, multi-input, shellbar, tabs, wizard.
- **Simple components are at parity.** About 40 display components (button, checkbox, icon, object-\*, info-label,
  generic-tag, text, tile, timeline, title, scrollbar, …) need nothing, or at most one or two tests.
- **The analysis turned up behaviour differences**, listed under [Differences found](#differences-found). Check those
  before writing tests for them, so the tests don't lock in a bug.

## Differences found

These came up while comparing and are behaviour, not coverage. Each needs a decision first: fix the port, or keep it and
record why. Then add a test either way.

| Component                    | Difference from upstream                                                                                                                                                                                                                                     |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| token                        | The test "selects with Space, clicks and Ctrl+A" never presses Space. Enter/Space don't emit `onTokenClick`. `closeClickHandler()` emits without an event. With `externalHiddenCount > 0` the tokenizer still opens its "n more" popover (upstream doesn't). |
| skeleton                     | `textLines = 0` renders one line (`Math.max(1, …)`); upstream renders none.                                                                                                                                                                                  |
| date-picker, datetime-picker | No `aria-describedby` to the message / state message. `aria-haspopup` is `dialog`; upstream uses `grid`.                                                                                                                                                     |
| datetime-picker              | Upstream's `dateChange` rules (no emit on `writeValue`, Cancel or a no-op) are untested here, so the `date` model may emit on `writeValue`.                                                                                                                  |
| action-sheet                 | Closes on Tab like upstream, but no test presses Tab.                                                                                                                                                                                                        |
| avatar-group                 | The overflow button defaults to `circle` (upstream: square). Vertical groups don't default the popover placement to the right. No `LiveAnnouncer` for item position.                                                                                         |
| nested-list                  | Up on the first row and Down on the last don't wrap; upstream wraps.                                                                                                                                                                                         |
| quick-view                   | `QuickViewGroup` renders `role="group"` without an accessible name.                                                                                                                                                                                          |
| notification                 | Action buttons don't get `aria-describedby` pointing at the header.                                                                                                                                                                                          |
| pagination                   | `itemsPerPage` isn't normalised (round down, default 10) as upstream does.                                                                                                                                                                                   |
| content-density              | Upstream's "restricting parent wins over child" rule is the opposite of our CSS, where the nearest ancestor wins.                                                                                                                                            |
| dynamic-page                 | Global actions don't collapse into an overflow at small sizes.                                                                                                                                                                                               |
| user-menu                    | The body doesn't stop click propagation.                                                                                                                                                                                                                     |
| feed-list, upload-collection | Upstream's XSS cases (`javascript:` author link, HTML in file names) have no test. Angular's sanitiser and `textContent` make us safe today, but nothing guards against a regression.                                                                        |

## Plan

One pull request per item, per `CLAUDE.md`: Conventional Commits, branched from `main`, with `pnpm check` passing.
Story PRs are `docs(<name>): …`, test PRs are `test(<name>): …`, and any source change a gap needs is its own
`fix(<name>)`/`feat(<name>)` PR first. Each component's "Gaps to fill" section in [`components/`](components/) lists
the exact stories (with proposed names) and test titles to add.

### Phase 1: "Open: …" stories (a11y coverage)

The cheapest, highest-value phase: a story whose `play` opens the overlay, and the a11y run picks it up. Each story may
surface axe failures. Fix them in the same PR when they're ours, or turn the rule off with a comment only when the SAP
theme is the cause. Grouped into PRs by family:

1. **Pickers:** date-picker, datetime-picker, time-picker, calendar (mobile/dialog).
2. **Select family:** select (list and mobile dialog), combobox, multi-combobox, multi-input, token, input-group.
3. **Menus:** menu (remaining), split-button, action-bar, tabs ("More"), toolbar (overflow), breadcrumb (collapsed),
   shellbar (user menu, product menu, product switch, overflow), side-navigation and nested-list (condensed popovers).
4. **Popovers:** popover (convert stories to `play`), avatar-group, overflow-layout, quick-view, rating-indicator,
   progress-indicator, micro-process-flow, pagination (items-per-page select), inline-help, form and input (value state
   message), feed-list (action sheet), card.
5. **Messages and dialogs:** message-toast, message-strip alerts, message-box (position, mobile), busy-indicator in a
   toast, illustrated-message in a dialog, wizard (dialog, stacked-steps action sheet), notification (service
   banners). Move product-switch/notification/dialog `autoOpen` stories to `play` where it's straightforward.

### Phase 2: behaviour tests, high priority

One `test(<name>)` PR per component. Do the [Differences found](#differences-found) items first, so the tests pin the
intended behaviour.

### Phase 3: missing example stories

One `docs(<name>)` PR per component, biggest first: list (12), popover (7), card (5), content-density (4, no stories
yet), dynamic-page (4), combobox (4), multi-combobox, multi-input, grid-list, dialog, tabs (3 each), then the components
with one or two missing examples (calendar, fixed-card-layout, input/textarea, scroll-spy, shellbar, upload-collection,
wizard, menu, …). Skip examples that are [blocked](#not-yet-ported) until the blocker is done.

### Phase 4: medium and low priority tests

The remaining `test(<name>)` PRs from the per-component table, in its order (avatar's image-loading suite, dialog
config options, slider, time, tree, toolbar, pagination, …). Low-priority items are often one or two tests. Several can
go into a single PR per family if the reviewers prefer, but by default it's one PR per component.

### Phase 5: blocked work (needs a decision)

The [blockers](#not-yet-ported) are features, not story or test gaps. Each needs a design decision (e.g. drag and drop
via CDK `DragDrop`, popover mobile mode) and a `feat` PR before its stories and tests can follow.
